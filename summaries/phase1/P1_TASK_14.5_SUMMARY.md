## Core Principles Established

### Pandit Event Philosophy
**Key Principle:** Pandit analytics observes activity, not merit.

**Pandit events describe actions, not performance.**

**Pandit events must not become evaluative.**

**Viewing ≠ understanding, agreement, or compliance.**

**Pandit events must not measure performance or quality.**

**Pandit events are descriptive records, not evaluative tools.**

**Pandit analytics is visibility-only.**

---

## Formal Definition (LOCKED)

### Pandit Interaction Events ARE:
- Records of explicit Pandit actions
- Post-action observations
- Neutral system facts

**Key Rule:** Pandit events describe actions, not performance.

---

### Pandit Interaction Events are NOT:
- Compliance checks
- Quality indicators
- Performance metrics
- Trust or reliability signals
- Governance triggers

**Key Rule:** Pandit events must not become evaluative.

---

## Allowed Pandit Event Categories (LOCKED)

### 1. Profile Management
- Profile created
- Profile updated
- Gallery updated

### 2. Availability Management
- Availability added
- Availability updated
- Availability removed

### 3. Dashboard Usage
- Dashboard viewed
- Reports page viewed

**Key Rule:** Viewing ≠ understanding, agreement, or compliance.

---

## Forbidden Pandit Events (LOCKED)

Pandit events must NEVER:
- ❌ Track responsiveness speed
- ❌ Track acceptance or rejection behavior
- ❌ Track compliance rates
- ❌ Track trustworthiness
- ❌ Track booking outcomes
- ❌ Track review sentiment

---

## Pandit Event Design Principles (LOCKED)

1. **Action-Only Principle:** Only explicit actions are tracked. No inferred behavior.

2. **Non-Punitive Principle:** Events must not be usable for enforcement. No thresholds or scoring.

3. **Governance-Isolated Principle:** Analytics cannot trigger moderation. Analytics cannot influence appeals.
